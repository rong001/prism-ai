# 多面先生 · 企业智能经营平台

面向 AI 应用负责人岗位的交互式产品演示，串联「商品 → 简报 → 创作 → 审核 → 投放 → 复盘」的业务流程。可直接由 GitHub Pages 托管，无需安装依赖或执行构建。

本项目根据用户提供的招聘 JD 设计。截图未披露公司全称，公开检索未确认招聘主体。品牌、客户、人物、供应商与经营数据均为虚构演示内容，不代表任何公司的真实经营情况或已确认的内部需求。

## 27 个模块

| 业务域 | 模块 |
| --- | --- |
| 工作台 | 营销项目中心、经营总览、我的任务 |
| 内容与创意 | 内容工厂、素材资产、品牌审核、短剧工作室 |
| 营销增长 | 投放管理、预算优化、渠道分析、增长实验 |
| 客户经营 | 客户中心、智能客服、会员运营、服务工单 |
| 供应链 | 商品管理、库存协同、采购管理、供应商 |
| 组织协同 | 需求与路线、职能助手、团队与应用 |
| 平台治理 | 模型与成本、知识中心、流程自动化、操作审计、系统设置 |

## 三套数据与三种主题

- 业务空间：「轻研美妆」「净序家清」「元气营养」。每套空间分别保存商品、项目、素材、客户、知识条目与经营数据。
- 视觉主题：「靛蓝」「云白」「石墨」，可在顶部或系统设置切换。
- 操作和偏好保存在当前浏览器的 `localStorage`，刷新后可继续；不同设备、浏览器或域名之间不会自动同步。清除站点数据会重置本地记录。

## 可演示的能力与实际边界

可以操作关联项目、编辑场景脚本、提交与审核素材、创建投放计划、查看经营指标、匹配产品知识、维护客服工单及经营任务，并在审计页面查看本地操作记录。

当前版本使用预置业务数据与本地规则计算，没有连接在线大模型、真实广告账户、客户渠道、采购系统或服务端数据库。投放与触达操作生成演示记录或清单，不会发送真实业务请求。短剧与素材功能演示企划和工作流程，不代表已经具备真实视频生成能力。所有收益、效率及经营数字均为演示数据或情景计算。

这是交互产品原型，没有生产级身份认证、服务端权限隔离、多人数据同步或服务 SLA。请勿输入真实客户隐私、账号密钥或商业机密。正式企业落地需补充后端、数据库、模型网关、业务接口授权、权限与监控。

## GitHub Pages 发布

1. 将本目录的全部文件上传到 GitHub 仓库的 `main` 分支根目录，保持平铺结构。
2. 在仓库 **Settings → Pages** 选择 **Deploy from a branch**，分支选 **main**，目录选 **/ (root)**，保存。
3. 等待 GitHub 完成发布，访问 Pages 页面提供的地址。之后向 `main` 根目录提交更新，GitHub Pages 会自动重新发布。

无需自定义 Actions 工作流。`.nojekyll` 用于声明普通静态站。页面采用 hash 路由，资源均为相对路径，支持 `https://<账号>.github.io/<仓库>/` 形式的项目地址。

此地址由 GitHub 账号、仓库和 Pages 设置持续维护，不是有固定到期时间的临时隧道；并非不可变的永久承诺。本项目用于作品与面试演示，不承载真实交易。
